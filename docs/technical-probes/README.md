# P06 可失败技术探针

P06 不实现真实卡牌，只用 `probe:*` 虚拟效果验证 P04 的架构前提。探针代码放在 `.replay.test.ts` 中，不导出为产品 API；路线失败时可以删除或重写，不形成内容迁移债务。

## Probe 1：复杂续算

固定六人状态创建 `probe:damage`，在每次玩家输入前执行 JSON 序列化/反序列化，再覆盖：

- 冰心诀无人反制，原效果取消且不造成伤害；
- 冰心诀被第二个取消反制，原伤害从保存续算点恢复；
- 全员放弃后伤害应用，目标进入濒死队列；
- 当前濒死对象获救后 HP 恢复，队列关闭。

## Probe 2：六份视图与命令边界

六名玩家各持唯一秘密牌。每份投影只包含自己的牌 ID；其他座位只有数量。只有当前优先玩家收到私密 `availableActions`。重复 `commandId` 返回首次结果，过期版本或越权命令不改变领域状态；两种“猜别人是否有响应牌”的非法命令得到同形拒绝。

## Probe 3：重启、超时与断联

快照保存绝对 `deadlineAt`、已处理超时键和 RNG cursor。截止前恢复仍得到原剩余时间；截止后恢复只产生一个系统超时。可选窗口放弃，强制窗口对稳定排序选项使用记录式随机值。15 秒操作期不因断联暂停；断联达到 60 秒只让未来窗口进入自动模式。

## 判定

三项全部绿色才把 ADR-0001 从“准备阶段接受”提升为“探针确认”。任何失败必须保留固定种子、初始快照、命令序列和最小反例，不能通过删除断言获得通过。
