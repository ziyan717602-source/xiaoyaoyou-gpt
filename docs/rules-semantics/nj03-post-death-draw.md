# SEM-010：NJ03 自伤后的摸牌续算

状态：`provisional-autonomous`；不是声称与旧 C# 黑盒行为等价。

## 最小状态与证据

当前玩家 A，HP=1，选择 NJ03 并指定 A 自己为摸牌者；无救援，其他队友存活，对局不结束。

- `PSDGamepkg/JNS/NC303.cs:128-133`：先 `Harm(player, 1)`，再 `G0DH` 给已选目标摸一张。
- 同文件 `710-712`：伤害无玩家来源，带 `FROM_NMB`。
- `PSDGamepkg/Artiad/Procedure.cs:177-185`：濒死检测会进入 `G0ZH`。
- `PSDGamepkg/XIG.cs:1218-1238,1287-1305` 和 `855-875`：摸牌分支没有检查目标是否存活，底层直接加手牌。

源码允许死亡之后仍给该目标发牌的组合路径；本节点没有能精确证明整条旧调度路径顺序的黑盒轨迹。不能静默把这解释为正常存活目标规则。

## 待维护者复核的问题与备选

NJ03 自伤死亡、且指定自己摸牌时，是否仍应得到一张死亡后的手牌？

1. 完全保留底层发牌：死者可持有新手牌；需同时明确后续死者手牌清理与复活继承。
2. 死亡后跳过后续摸牌，不消耗牌堆（本次临时选择）。
3. 改为先摸牌再处理濒死（不采用，会改变救援可用牌和时序）。

## 临时执行与影响

先完成现有伤害、减伤响应、濒死、死亡及胜负；只有对局未结束且已选摸牌目标仍存活才摸一张。来源死亡但目标仍活着时仍摸牌；目标已死亡则显式无后续摸牌。对局已结束只清理持有的 NPC，不发奖励或摸牌。

这是对上述潜在旧行为的明确暂行偏离，目的是保留死亡清理、不增加幽灵手牌，并保持确定性和实体守恒。影响 NPC NJ03 及调用同一行动的未来卡牌；不改变一般 G0DH 或其它卡牌时序。没有等待用户答复的阻塞，后续可用更高等级证据替换此裁定。

验证：`npc-effects.test.ts` 的 NJ03 救援后摸牌、来源死亡/目标存活摸牌、自选目标死亡不摸牌，以及 NJ05 终局后清理。恢复与事件日志必须得到相同结果。
