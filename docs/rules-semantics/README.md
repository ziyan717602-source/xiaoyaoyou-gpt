# 新引擎规则语义合同

本目录冻结“新引擎必须表达什么”，不规定 UI 组件，也不把旧 C# 的线程、字符串拼接或全局状态照搬进新实现。机器真源是 [`contracts/semantics.contract.json`](../../contracts/semantics.contract.json)，运行 `npm run semantics:verify` 检查完整性和关键反例。

证据优先级仍为：C# 实际分支 → SQLite 行/描述 → 旧协议轨迹 → 项目规则文档 → 临时决定。无法由旧实现唯一确定的地方进入 [`decisions.md`](decisions.md)。

## 1. 生命周期

对局按以下状态单向推进：

`room-open → seating → ready-check → hero-selection → setup → turn ↔ resolving → finished → archived`

- 房间只允许六个固定座位；准备后不再加入新玩家，也没有观战者。
- `turn` 保存当前回合玩家和阶段；需要处理效果或玩家输入时进入 `resolving`，完成后返回保存的续算点。
- 回合阶段的稳定名称为 `turn-start / event / action / encounter / battle / reward / discard / turn-end`。`discard` 对应旧版奖励阶段后的手牌上限整理；旧 `R1OC` 等代码只保留为 oracle 映射，不成为新协议 API。
- `finished` 后游戏状态不可变，只允许写入归档元数据。

## 2. 稳定身份与因果链

`matchId / commandId / eventId / effectId / windowId / choiceId / playerId / canonical contentId` 都是稳定 ID，禁止用数组下标、牌名或当前栈位置代替。

一个效果实例至少包含：

- `effectId`：本次实例的唯一 ID；
- `parentEffectId`：产生它的父效果，没有则为 `null`；
- `source`：角色、卡牌、技能、系统超时或断联事件；
- `targets`：创建时的目标快照，结算前仍须复核合法性；
- `kind / step / status / payload`：可序列化的规则状态。

取消操作必须指向 `effectId`。相同卡牌在同一窗口打出两次是两个实例，不能通过“取消 TP01”这种名称级操作误伤另一个实例。

领域事件按对局内严格递增 `sequence` 追加，并记录 `causationCommandId` 或 `causationEventId`。状态只由事件 reducer 产生；网络发送、数据库写入和定时器不进入 reducer。

## 3. 命令、幂等和拒绝

客户端命令带 `commandId`、单调递增的 `clientSequence`、`expectedVersion` 和仅供审计的 `clientIssuedAt`。服务端依次检查身份、座位权限、重复命令、序号、版本、窗口/截止时间和 `availableActions`。`clientIssuedAt` 由客户端提供，绝不能用于授权、命令排序或截止时间判断；这些判断只使用服务端接收时间和已持久化的绝对期限。

- 相同 `commandId` 重试：返回第一次的同一结果，不追加事件。
- 已使用或倒退的客户端序号：`stale-sequence`。
- 基于旧状态提交：`stale-version`。
- 已关闭/过期窗口：`expired-window`。
- 当前服务端没有提供该动作：`not-available`。
- 操作别人私密选项或伪造座位：`forbidden`。
- 对局结束后动作：`match-finished`。

拒绝消息不得透露私密合法选项、他人手牌或“差一点合法”的原因。

## 4. 续算点和等待点

每次等待玩家输入都持久化为一个窗口和一个续算点。续算点只允许包含 `continuationId / effectId / step / locals / resumeWith` 等 JSON 数据，禁止 closure、Promise、线程、socket 和对象引用。

窗口必须列出：合法玩家、合法动作/选项、当前优先者、已放弃者、打开时间、绝对截止时间、超时策略和续算点。任何时刻最多有一个面向玩家的顶层等待窗口；嵌套效果通过父子续算栈表达，不通过同时挂多个 socket 回调表达。

## 5. 响应窗口和冰心诀

响应权从效果来源的下一座位开始，按座位顺序轮转。放弃只对当前窗口有效；任一合法响应会清空“连续放弃”并创建子效果。当前所有合资格玩家连续放弃一次后窗口关闭，父效果进入结算。

冰心诀和类冰心诀统一为 `CancelEffect(targetEffectId)`：

1. 原牌创建父效果并停在保存的续算点；
2. 玩家提交冰心诀命令，服务端先验证并支付代价；
3. 冰心诀成为子效果，目标是父效果 ID；
4. 子效果成功结算，父效果变为 `cancelled`，原效果不再执行；
5. 若第二个反制取消了这个冰心诀子效果，父效果仍为 `pending`，从原续算点恢复；
6. 父窗口在子效果来源的下一座位重开，之前的放弃记录失效并重算存活/连接资格。

已经支付的响应代价不自动退还。只有具体规则明确写“返还/收回”时才产生补偿事件。没有合法目标的动作不会出现在 `availableActions`；命令接受后目标才消失则产生显式 `EffectFizzled(no-legal-target)`，默认不退成本。

## 6. 伤害批次

伤害严格按以下管线处理：

1. 规范化整个伤害批次；
2. 应用替换，每个替换效果 ID 对同一伤害项至多一次；
3. 应用加成；
4. 应用减免；
5. 最低降到 0，不产生负伤害；
6. 对已规划批次依次完成可用的卡牌防御窗口；
7. 同批剩余项全部同时写入 HP；
8. 追加应用事件；
9. 入队“伤害后”触发；
10. 整批完成后才检测濒死。

同层效果按 `priority → source seat → effectId` 排序。替换循环由“效果 ID 已应用集合”终止。禁止对批次第一人扣血后立刻打开救援，从而让救援结果影响同批后续伤害。

## 7. 濒死、救援、死亡和胜负

完整 HP/伤害批次后，仍 `alive && hp === 0` 的角色进入濒死队列，按检测快照的座位号排序；一次只处理一个当前救援目标。

- 救援优先权从当前濒死者本人开始按座位轮转。
- 救援令其 HP 大于 0 后，移出队列并重新检测，再处理下一个目标。
- 全体合资格玩家连续放弃且目标仍为 0 HP，才把目标标为死亡。
- 死亡先触发弃牌/装备/NPC、死亡后技能和队列重算，之后才检查胜负。
- 一队仍有存活角色且另一队没有：前者胜；双方均无存活角色：平局；双方都有：继续。

“死亡角色不能响应”是默认不变量；明确标注为 after-death 的规则可例外，必须成为独立效果来源。

## 8. 随机与重放

随机状态为 `algorithm / seed / cursor`。服务端在开局前生成秘密 seed 并保存承诺值，结束后可揭示 seed 供审计；客户端输入不进入随机源。算法固定为版本化的 `sha256-counter-v1`，有界取值必须拒绝采样，禁止直接取模。洗牌使用固定 Fisher–Yates；强制随机选择先按稳定 option ID 排序，再用记录的随机值选择。事件记录候选集合哈希、结果和 cursor 范围。

相同快照、事件和 RNG 状态必须得到逐字节相同的新状态。不得调用系统时间、`Math.random()` 或无记录的集合迭代次序来决定规则结果。

## 9. 15 秒操作、60 秒断联与重启

- 每个玩家窗口的操作时限为 15 秒。
- 可放弃动作到期生成服务端 `TimeoutPass`；不可放弃动作对稳定排序后的合法选项执行确定性随机。
- 断联不暂停 15 秒。60 秒是在线状态宽限：到期后该座位进入自动模式，之后的新窗口无需再等待 15 秒，直到认证重连。
- 重连得到该座位当前私密视图和开放窗口，不恢复已过期命令。
- 截止时间保存为绝对时间；服务重启按原截止时间计算剩余值，绝不重置为 15 秒。
- 停机期间已经过期的窗口在恢复后追加至多一个幂等超时命令。

## 10. 隐私分区

- `public`：座位、队伍、角色、HP、装备、已声明效果、手牌数量；
- `team`：已公开的支援状态和规则明确要求的队内结果；
- `player-private`：自己的手牌、自己的私密选项和命令结果；
- `server-secret`：牌堆顺序、未揭示牌、他人手牌、RNG seed。

队友默认不能看彼此手牌。服务端为每个接收者从权威状态重新派生视图，不能先构造含秘密的共享对象再原地删字段。公开日志、错误详情、消息数量和稳定“加密牌 ID”都不得成为侧信道。

## 11. 快照、事件日志和版本

快照携带 persistence/ruleset/protocol 版本、matchVersion、最后事件序号、状态和保存时间。快照后的事件带哈希链顺序重放；事件与命令幂等结果原子提交。

版本升级只能使用显式、可测试的前向迁移器。遇到未知版本时拒绝启动该对局并保留原数据，禁止在载入代码中猜字段含义或静默写回。
