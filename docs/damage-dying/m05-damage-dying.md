# M05 伤害、濒死、救援与死亡

状态：pass。

M05 以标准包天雷破（JP05）作为可取消伤害入口，以灵葫仙丹（TP02）作为濒死救援入口。数据库牌面与 C# 一致：天雷破指定一名玩家造成 2 点雷属性伤害；灵葫仙丹在玩家 HP 为 0 时支付一张，使当前目标恢复 2 HP。

## 冻结状态机

1. 天雷破先支付并创建稳定效果 ID，沿用 M04 响应窗口；被冰心诀取消时不扣 HP。
2. 原效果通过后执行整个伤害批次：规范化、替换、加成、减免、最低归零；CONTENT-STANDARD 的防御牌可在此对已规划批次建立可序列化响应，随后才整批写入剩余 HP、进入伤害后阶段并检测濒死。
3. `alive && hp === 0` 的玩家按检测快照中的座位号进入同一濒死批次；每次只打开一个当前救援目标。
4. 救援优先权从当前濒死者本人开始，按仍存活座位轮转。当前优先玩家可以支付自己的 TP02 或放弃；其他五人没有救援动作。
5. TP02 使目标 HP 从 0 恢复到 2 后立即关闭该目标，重检后继续快照中的下一名濒死者。
6. 全部合资格玩家连续放弃且目标仍为 0 HP 后，目标死亡；手牌、武器和防具按实体 ID 进入弃牌堆，再完成显式死亡后阶段。
7. 同一濒死批次全部目标处理完后才重算胜负，避免双方同批团灭时提前宣布一方获胜；双方均无存活者按 `SEM-003` 判平局。

伤害修正框架在 M05 固化顺序与一次性替换集合；尚未迁移的具体角色/装备修正不会伪造成空规则。死亡后阶段同样先建立稳定事件边界，具体技能随内容节点接入。

CS01C 已在“最低归零”与“整批 HP 写入”之间接入隐蛊防御窗口。该扩展不改变 M05 的整批写入与整批后濒死不变量；被防止的项先从计划批次移除，剩余项仍一次应用。

TP02 在自己技牌阶段为自己回血的普通用法尚未进入 M05；本节点只完成 C# 的濒死救援模式。普通用法在 `CONTENT-STANDARD` 按同一实体卡 ID 接入，目录状态不得在此提前标记整张牌完成。

## 时间、恢复与隐私

救援等待点使用与 M04 相同的服务端绝对 15 秒期限，断线和重启不重置。M05 负责保存/恢复期限与状态；系统自动放弃由 M06 统一接入命令管线。

濒死顺序、当前目标、当前优先者、放弃记录和期限公开；只有当前优先玩家收到自己的 TP02 实体操作。其他玩家只知道其手牌数量，不能从 `availableActions`、错误详情或额外消息推断其是否持有救援牌。

## 证据差异

B 级黄金轨迹为验证濒死顺序而抽象手牌为数量，最终状态没有模拟 C# `G0ZW` 后续卡区清理。C# `XIG.cs` 在死亡标记后的优先级阶段明确触发手牌、装备等清理；因此生产合同采用源码的完整死亡清理，黄金轨迹只作为救援轮转与 HP/存活状态证据。

旧 C# 通过并发输入收集救援，不能证明稳定到达顺序；黄金轨迹为了重放规范化为固定座位 1..6。P04 语义合同已经冻结为“从当前濒死者本人开始按座位轮转”，M05 沿用该确定性裁定并在机器合同中显式记录，避免线程调度决定规则结果。
