# 目标架构

## 总体结构

```text
PC/手机浏览器
  React UI + 本地展示状态
          │ HTTPS / WebSocket
          ▼
云端接入层
  身份、房间、命令校验、重连
          │ 每局单线程命令队列
          ▼
确定性规则引擎
  MatchState + EffectStack + ReactionWindow
          │ 事件日志 + 周期快照
          ▼
PostgreSQL
```

第一阶段采用单体服务。只有在真实并发数据证明有必要时，才引入 Redis、独立匹配服务或多区域部署。

开发阶段只运行本地环境；本地恢复、网络故障和完整验收稳定后，再补充云端部署设计。生产架构不因此依赖本机文件或进程内持久状态。

## 包边界

- `packages/protocol`：跨进程消息契约、协议版本与标识类型；不得包含规则。
- `packages/engine`：纯规则内核；不得访问网络、数据库、文件系统和真实时间。
- `apps/server`：权威房间 Actor、身份、连接、持久化和超时调度。
- `apps/web`：玩家视图、交互与动画；不裁定结果。

## 命令处理契约

每个客户端命令必须携带：

- `commandId`：幂等去重；
- `matchId` 与 `playerId`；
- `expectedVersion`：拒绝基于过期状态的操作；
- `protocolVersion`；
- 命令类型及经过结构校验的参数。

处理流程：

1. 校验会话、房间和协议版本；
2. 以 `commandId` 去重；
3. 检查 `expectedVersion`；
4. 将命令串行送入该局 Actor；
5. 引擎产生领域事件和新状态；
6. 原子保存事件与版本，按玩家投影并推送视图；
7. 客户端确认新版本。

## 持久化与恢复

- 每个已接受命令产生不可变事件记录。
- 定期保存完整快照；恢复时从最近快照重放后续事件。
- 快照包含随机数状态、牌堆顺序、效果栈、响应窗口、待选择项与规则集版本。
- 任何时候执行 `JSON.stringify(state)` 都不得丢失续算所需信息。
- 超时是由服务端提交的显式命令，也进入事件日志。

## 超时与掉线

- 每个普通操作和响应窗口的行动时限为 15 秒。
- 可选动作超时后执行“放弃”。
- 不允许放弃的强制选择超时后，由服务端从当前合法选项中随机选择。
- 强制选择使用对局内可重放的伪随机数状态，结果写入超时命令和事件日志；禁止客户端随机或直接调用未记录的 `Math.random()`。
- 掉线不会暂停整局，也不会延长当前 15 秒行动时限，避免玩家通过主动断线获得额外思考时间。
- 断联满 60 秒后进入自动决策状态：后续轮到该玩家时不再重复等待 15 秒，立即按“可放弃则放弃、否则可重放随机选择”处理。
- 60 秒内重连可以恢复座位和当前尚未超时的选择；已经超时的动作不会回滚。
- 超时产生独立命令和日志，回放时不重新等待真实时间。

## 玩家与观察权限

- MVP 固定六名玩家。
- 不提供观战入口、观战连接或观战视图。
- 运维诊断通过受控日志和离线回放完成，不伪装成观战玩家。

## 明确不做

- 不让浏览器执行权威规则；
- 不把每张卡写成一个网络接口；
- 不依赖 WebSocket 连接本身表示玩家身份；
- 不在规则层调用 `Date.now()`、`Math.random()` 或数据库；
- 不为了“灵活”而在 MVP 前设计通用规则 DSL。
