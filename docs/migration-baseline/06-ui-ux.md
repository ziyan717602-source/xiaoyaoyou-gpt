# UI/UX 基线

## 设计目标

界面首先帮助玩家理解“正在发生什么、为什么轮到我、我能做什么”，其次才是还原旧客户端外观。

## 响应式信息架构

### 桌面

```text
┌────────── 对手与队伍状态 ──────────┐
│                                    │
│       当前战斗 / 事件 / 响应链       │ 事件日志
│                                    │ 规则提示
├────────────────────────────────────┤
│ 手牌横向区             情境操作托盘  │
└────────────────────────────────────┘
```

### 手机竖屏

```text
┌──── 玩家席位摘要，可横向切换 ────┐
│ 当前事件、目标与响应链            │
│ 选中卡牌/角色的详情抽屉           │
├───────────────────────────────────┤
│ 可横滑/展开的手牌                  │
│ 固定：主要操作 / 确认 / 放弃       │
└───────────────────────────────────┘
```

桌面与手机共享状态和组件，但不是把固定桌面画面等比缩小。

## 情境操作托盘

服务端玩家视图提供 `availableActions`，客户端据此渲染：

- 事件标题与来源；
- 当前待行动玩家；
- 合法目标或卡牌；
- 必选数量、可否取消、剩余时间；
- 明确的确认与放弃按钮；
- 规则摘要与完整说明入口。

不使用固定七个技能按钮或客户端自行猜测可点击对象。

## 复杂场景

### 冰心诀

响应面板展示效果链，例如：

```text
李逍遥使用【某牌】 → 等待响应 → 赵灵儿使用【冰心诀】 → 原效果已取消
```

每个节点可展开查看来源与目标。未轮到的玩家能看到公开的等待状态，但不能看到别人有哪些合法私密响应牌。

### 濒死

- 顶部显示全局濒死横幅和待救援角色；
- 可用救援牌高亮，但高亮只在持有者自己的视图发生；
- 多人濒死时明确当前救援对象和后续顺序；
- 放弃按钮说明本次放弃的范围，避免误解为整轮不再响应。

## 原型验收状态

至少准备以下静态/模拟状态，而不是只画默认棋盘：

- 自己回合可出牌；
- 等待他人操作；
- 选择一个与多个目标；
- 冰心诀响应窗口；
- 多人濒死救援；
- 断线、重连中和状态过期；
- 手牌很多、技能很多和文本很长；
- 游戏结束与结算摘要。
