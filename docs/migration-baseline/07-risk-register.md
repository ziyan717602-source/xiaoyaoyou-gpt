# 风险登记册

| ID   | 风险                                   | 影响                               | 当前措施                                               | 触发升级条件                   |
| ---- | -------------------------------------- | ---------------------------------- | ------------------------------------------------------ | ------------------------------ |
| R-01 | 旧代码与美术资源的第三方授权证据不完整 | 公开仓库、部署或商业化存在权利风险 | 已获维护者同意公开仓库；继续盘点第三方许可证与素材来源 | 首次公开推送、部署公网或商业化 |
| R-02 | 规则来源互相冲突                       | 实现反复返工                       | 建立权威顺序和裁定日志                                 | 同一场景出现两种合理解释       |
| R-03 | 嵌套响应仍依赖调用栈                   | 无法恢复、重连失败                 | 显式效果栈和待选择状态                                 | 规则函数出现等待 I/O           |
| R-04 | 一次迁移全部内容                       | 长期无可玩版本                     | 按纵向切片和规则包推进                                 | 新增内容不服务首个切片         |
| R-05 | UI 在规则完成后才设计                  | 手机交互返工                       | 用模拟状态提前做响应式原型                             | 新规则无法用现有操作托盘表达   |
| R-06 | 客户端泄露隐藏信息                     | 破坏公平性                         | 服务端玩家视图投影和隐私测试                           | UI 收到无权得知的完整状态      |
| R-07 | 事件日志无限增长                       | 存储和恢复变慢                     | 周期快照与保留策略                                     | 单局恢复超过目标时间           |
| R-08 | 过早微服务化                           | 运维复杂度超过收益                 | MVP 单体、每局 Actor 隔离                              | 单实例测量证明确有瓶颈         |
| R-09 | 自定义规则 DSL 过度设计                | 难调试、难迁移                     | 先用类型化处理器与普通代码                             | 重复模式有足够样本后再评估     |
| R-10 | 二进制资源膨胀 Git                     | 克隆慢、历史臃肿                   | Git LFS；沿用 `_Full` 忽略                             | 确认授权且决定正式资源管线     |

风险负责人和截止时间将在进入第一纵向切片时补充。
