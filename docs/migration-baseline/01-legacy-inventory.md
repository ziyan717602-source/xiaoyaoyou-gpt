# 旧系统清单

## 解决方案结构

| 模块            | 原职责                             | 迁移处置                           |
| --------------- | ---------------------------------- | ---------------------------------- |
| `PSDCenter`     | 六人匹配、大厅聊天、房间协调与重连 | 行为参考；由统一云端房间服务替代   |
| `PSDGamepkg`    | 每房间独立权威进程、完整规则结算   | 核心行为证据；不直接进入生产环境   |
| `PSDBase`       | 玩家、卡牌、技能、棋盘及共享接口   | 数据模型参考；重新定义可序列化模型 |
| `PSDClientAo`   | 固定尺寸 WPF 图形客户端            | 交互信息参考；布局不移植           |
| `PSDClientZero` | 命令行客户端                       | 协议与调试行为参考                 |
| `PSDDorm`       | 辅助功能                           | MVP 暂不迁移                       |
| `PSDRisoLib`    | 图片、卡图、语音资源               | 授权确认后按 Web 格式迁移          |

旧解决方案还引用已缺失的 `sharpuil` 与 `Wangpengfei` 项目，不能视为可直接完整构建的生产基线。

`reference/docs` 中还存在此前整理的范围、卡牌信息和流程资料。这些资料完整保留，但其中的“硬性约束”或规则结论在维护者确认前不自动覆盖本基线的规则权威顺序。

## 规模快照

- 旧参考目录约 1,558 个文件、186 MB。
- `PSDGamepkg` 约 35,000 行 C#；`PSDClientAo` 约 19,000 行。
- 规则数据库包含约 123 名角色、322 个技能、68 张基础卡、67 个怪物、97 个 NPC、47 个事件和 53 个额外包条目。
- 资源库约 1,200 个图片/音频文件。
- 未发现系统化自动测试。

以上数字用于估算和跟踪，不作为规则正确性的证据。

## 当前运行模型

```text
WPF/CLI 客户端
      │ TCP 字符串协议
      ▼
PSDCenter ──匹配六人──► 为房间启动 PSDGamepkg.exe
                              │
                              ├─ 阻塞等待玩家输入
                              ├─ 通过 C# 调用栈续算嵌套效果
                              └─ 广播公开状态并单发私密状态
```

主要限制：

- 每个房间一个进程和端口，不适合弹性云端调度；
- 浏览器不能直接使用旧 TCP 协议；
- 线程、阻塞读取及递归调用保存了隐式结算状态；
- 重连只恢复棋盘快照和最近提示，不能可靠恢复整个嵌套效果栈；
- 多处使用紧凑字符串协议，规则、网络与 UI 选择语法相互耦合；
- 固定六人与固定窗口布局写入了旧实现。

## 规则实现方式

数据库保存编号、描述、触发时机与优先级；C# 通过方法命名和反射绑定具体效果。事件代码如 `G0OH`、`G1TH`、`G0ZH`、`G0CD` 形成了一套事实上的触发系统。

迁移时保留旧代码作为“行为预言机”，但不保留以下实现方式：

- 在规则函数中直接等待网络输入；
- 依赖当前线程或函数调用栈恢复结算；
- 通过拼接字符串传递未校验的规则参数；
- 用全局最近提示充当可靠重连状态；
- 让客户端解释协议字符串来推导合法动作。
