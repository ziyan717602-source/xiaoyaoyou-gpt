# 旧版指定场景 Oracle 降级报告

日期：2026-08-19

## 已完成的实机边界

- 锁定的 .NET Framework 4.0 参考程序集可以构建 `PSDBase → PSDGamepkg/PSDClientZero` 最小子集。
- 六个 Node TCP 客户端使用 .NET 7-bit UTF-8 字符串帧连接旧服务端，完成加入、准备、座次和随机选角。
- 两次相同输入证明座次、角色与并发帧到达次序不稳定；原始实机记录保存在本地忽略目录 `artifacts/oracle/`。

## 为什么不继续硬驱动指定局面

旧服务端没有可发现的测试场景注入接口、固定随机种子或稳定的存档载入入口。要实机得到“持有冰心诀并在指定技牌上响应”和“两个指定角色同时 0 HP”需要控制随机座次、选角、牌堆、抽牌、怪物/事件及多线程响应时序。继续修旧 WPF 客户端或反复刷随机局面不能产生可重复证据，也不服务于云端迁移目标。

因此依据 `P02-09` 停止扩张旧客户端修复范围，切换为以下组合证据：

1. 实机 TCP 握手轨迹证明传输帧、广播和连接私密边界；
2. SQLite 行与哈希证明 TP01/TP02 等内容身份；
3. C# 分支行号与文件哈希证明阶段、取消、濒死、救援、死亡和胜负重算顺序；
4. 规范化 JSON 轨迹固定输入和最终状态，由仓库脚本确定性重放。

## 证据等级和限制

三条指定规则轨迹均标为 B 级，不声称是旧进程完整实机录制。归一化层刻意不固定旧程序本身无法固定的随机值和线程日志顺序，只固定迁移引擎必须保持的状态语义。P04 会把这些轨迹升级为新引擎的可执行契约，并通过反例、属性测试和浏览器多客户端测试继续验证。
