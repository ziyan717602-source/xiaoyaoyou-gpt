# M01 房间生命周期

M01 只负责“六名玩家可靠进入同一局”的边界，不提前混入选角、组队或牌局规则。房间固定经历 `open → started → ended`；没有观战、动态扩容、账号注册或座位复用。

## 身份与入座

- `POST /api/rooms` 匿名建房并占据 0 号座位；`POST /api/rooms/join` 使用八位人工友好邀请码加入最小空座位。
- 房间和玩家 ID 均由服务端生成 UUID。重连凭证由 32 字节密码学随机数生成，明文只返回一次；SQLite 仅保存 SHA-256，比较使用定时安全函数。
- 邀请码用于定位房间，不是认证凭证。读取房间、准备、开始和结束均要求玩家 ID 与 Bearer 重连凭证同时匹配。
- 昵称去除首尾空白并压缩连续空白，最终长度为 1–24 个 JavaScript 字符；昵称不承担身份作用。

## 状态与并发

- 第六个座位占用后，后续加入得到 `room-full`；开始后得到 `room-not-open`。
- 每次有效变化递增房间 `version`。客户端 mutation 必须提交 `expectedVersion`；过期版本得到 `stale-version`，应重新读取当前视图后决定是否重试。
- 准备可由每名玩家设置；只有房主能开始，且必须恰好六座位全部准备。只有已开始房间可以由房主结束。
- mutation 以 `(roomId, commandId)` 幂等。相同玩家和命令类型重试返回原收据并标记 `duplicate: true`；换玩家或换命令类型复用相同 ID 得到 `command-id-reused`。

## 连接、重启与替换

- 浏览器先通过 HTTP 获得会话，再连接 `/ws`，在首帧提交房间 ID、玩家 ID 和重连凭证。配置 Origin allowlist 后，请求必须携带且匹配 Origin。
- 同一座位的新认证连接替换旧连接，旧连接以 4000 关闭；旧连接的迟到 `close` 不会把新连接标成离线。
- 连接状态是可恢复的呈现信息。服务启动时将残留在线标记统一转成离线并只把房间版本递增一次；房间、座位、准备状态、matchId 和 token hash 全部保留。
- 优雅停服先发送 `server-draining` 并关闭 WebSocket，再关闭 SQLite；停服触发的迟到回调不会访问已关闭数据库。

## 失败与安全边界

HTTP 使用稳定错误体 `{ "error": "code" }`：无效输入 400，错误座位/凭证 403，房间不存在 404，满员/状态冲突/过期版本 409，限流 429。创建/加入限制为每 IP 每分钟 12 次，房间 HTTP 为每 IP 每秒 40 次；WebSocket 是每连接每秒 20、突发 40，首帧认证连接上限 100，帧和 HTTP body 上限 64 KiB。

M01 不声称 60 秒断联超时、自动选择、正式牌局事件恢复或 UI 已完成；这些分别属于 M06、M02–M05 和 M07。M01 的 `matchId` 只是后续局初始化的持久锚点。

## 验证

```powershell
npm run rooms:verify
npm run check:full
```

房间单测覆盖六座位、非法转移、权限、版本冲突、幂等收据、命令 ID 冲突、token 哈希和重启持久化。真实网络测试覆盖六个 HTTP 会话与六条 WebSocket、服务重启后重连、同座位替换、恶意/缺失 Origin 和错误 token；测试必须零未处理后台异常。
