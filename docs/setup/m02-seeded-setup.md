# M02 确定性选角与开局

M02 把 M01 的六个稳定身份转换成可重放牌局初态。房间座位仍用于认证和重连，不因开局改号；秘密服务端 seed 另行洗出 `turnOrder`，其偶数位置属于 1 队、奇数位置属于 2 队，因此两队各三人，`turnOrder[0]` 是先手。这是 `SEM-007`，对应 C# 联机端先随机重排 UID、再按 UID 奇偶分队并从 UID 1 开始的行为，同时避免破坏浏览器版稳定座位。

## 选角

标准包+凤鸣玉誓目录有 34 名范围角色。C# `HeroLib.ListAllJoinableHeroes` 把赵灵儿·梦蛇、魔尊、龙葵·红和湮世穹兵视为不可直接加入的形态，故直接选池为其余 30 名。

三选一模式先从 seed 洗过的池中分配 24 个互不重复角色：每人三个私有候选及一个私有替补。替补要替换的候选下标也在开局准备时由同一 RNG 预先决定，因此六名玩家命令到达的先后不会改变彼此随机结果。每人最多使用一次 `reroll-hero`，再以 `choose-hero` 选择当前候选；全部选择前，其他玩家只能看到“谁已选定”，看不到其候选或角色，全部完成后同时公开角色和基础属性。

## 牌堆与初始手牌

目录中 24 个普通卡牌条目展开为 56 个唯一物理序列，凤鸣玉誓的两项 `special-card` 不混入普通牌堆。牌堆用同一版本化 RNG 执行 Fisher–Yates；角色全部选定后，按 `turnOrder` 依次给每人连续三张顶牌，留下 38 张。实体 ID 带物理序列，任何时点都能验证 56 张守恒。

## 随机与恢复

`sha256-counter-v1` 严格使用语义契约的输入：4 字节 seed 长度、8 字节大端无符号 cursor、seed UTF-8 字节。有限范围采用拒绝采样，禁止直接对原始值取模。准备消费顺序固定为回合顺序洗牌、角色池洗牌、普通牌堆洗牌、六次替补下标；玩家视图只有 seed 的 SHA-256 承诺，seed 和牌堆顺序仅在服务端快照中。

房间从 `open` 进入 `started` 与 match 初始快照在同一个 SQLite 事务内。选角命令由单局 Actor 串行化；事件、内容指纹幂等收据、match 版本和等待点快照原子提交。中途重启从快照加事件恢复，完全相同命令重试返回旧收据；同 ID 换内容或换玩家稳定拒绝。

## 边界

M02 初始化角色基础 HP、战力、命中、手牌、队伍和先手，但不声称角色技能、卡牌效果或正式回合阶段已经实现；这些从 M03 与内容节点开始。选角 15 秒自动随机属于 M06，此节点只保证该随机选择所需候选和确定性 RNG 已存在。

npm run setup:verify
npm run check:full
