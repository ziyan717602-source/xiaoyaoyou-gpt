# M04 响应窗口、冰心诀与反制

状态：pass。

M04 在 M03 的卡牌命令管线上加入可序列化效果栈、单一顶层响应窗口和 JSON 续算点。C# 与黄金轨迹明确证明：卡牌先支付并进入待处理状态，合法冰心诀消耗自身并取消当前卡牌，原效果不执行。旧服务端并发响应顺序不稳定，因此新引擎使用 P04 已冻结的座位优先权。

## 状态机

以鼠儿果作为首个可闭环的可取消原效果：

1. 当前玩家提交鼠儿果并选择一个存活目标；服务端支付卡牌、创建稳定 `effectId`，但不立即摸牌。
2. 从效果来源下一名存活座位开始打开 15 秒响应窗口。只有当前优先者收到 `pass-reaction`，若其持有冰心诀还收到自己的 `play-reaction-card`。
3. 全部合资格玩家连续放弃后，鼠儿果只结算一次，目标摸两张。
4. 冰心诀被接受时立即支付，创建指向当前效果 ID 的子取消效果，并为该子效果打开新窗口。
5. 子窗口全员放弃后，冰心诀结算并取消目标；若目标是原鼠儿果，原效果不摸牌。
6. 若另一个冰心诀取消了第一个冰心诀，原鼠儿果保持 `pending`，恢复原窗口，清空旧放弃记录，并从反制来源下一名合资格座位重开。

嵌套深度由实际物理冰心诀数量自然限制，不在代码中写死两层。已支付响应牌默认不返还。

## 时间、恢复与隐私

窗口的 `openedAt/deadlineAt` 由 MatchService 传入的服务端接收时间生成，客户端 `clientIssuedAt` 只记审计。每次优先权实际转移得到新的 15 秒截止时间；断联不能重置当前截止时间。M04 保存并重放期限，但真正产生系统超时命令属于 M06。

快照必须同时保存效果栈、当前窗口、父窗口续算、优先下标、已放弃者和绝对截止时间。窗口中重启后六名玩家收到各自重新投影的视图；只有当前优先者知道自己是否可用冰心诀，其他玩家不能从动作、错误详情或额外消息推断其手牌。

## 权威边界

- 单层冰心诀取消来自 C# 与 `legacy-bingxin-response` B 级黄金轨迹。
- 取消被取消后的父效果恢复采用 `SEM-004 provisional-autonomous`；C# 的字符串递归不能稳定证明并发到达顺序。
- 队友不共享响应牌能力采用 `SEM-006`。
- 超时自动放弃、60 秒断联自动模式属于 M06；M04 不伪造定时器已完成。
