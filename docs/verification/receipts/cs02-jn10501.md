## 规则证据

- SQLite：`OCCURS=R#GR`、`ONCE=0`，描述为自己的技牌阶段可将任意数量手牌交给一名或多名玩家。
- `PSDGamepkg/JNS/XJ405.cs:201-236`：合法性要求本人有手牌且存在另一名 `IsTared` 同队角色；每次输入选择本人一至全部手牌和恰好一个其他存活队友，动作发送一次显式 `G0HQ`。因此“多名玩家”通过不受次数限制的多次发动实现。
- `PSDGamepkg/XIG.cs:1015-1042`：`G0HQ` type 0/subtype 1 从来源移除明确牌实例并导入接收者手牌；牌面只发送给来源和接收者，其他玩家只收到数量。

## 已验证边界

- 只有存活的原生阿奴在自己的行动阶段、本人至少有一张手牌且存在另一名存活队友时获得动作；候选是全部当前手牌，最少选一张、最多选整手，目标只含其他存活队友。
- 服务端拒绝空集、重复牌、外来牌、未知牌、伪造技能，以及本人、对手、死亡和多目标输入；非法命令不改变版本或牌区。
- 一个权威事件按命令顺序把所选实体从来源手牌追加到单个接收者手牌；对手牌区、装备、弃牌堆和总卡牌集合不变。
- `ONCE=0` 不写入阶段次数标记。成功后只要仍有手牌和合法队友就继续开放，可在同一阶段向不同队友多次转移；手牌耗尽后动作消失。
- 技能不创建卡牌效果或冰心诀窗口。15 秒行动超时不发动、不预先转移牌，随后完全复用普通回合推进。
- 动作及来源手牌 ID 只投影给阿奴；转移后的牌 ID 只存在于接收者本人手牌投影。JSON 回放覆盖两次转移；六个真实 WebSocket 覆盖首次转移、SQLite 中途重启、非法对手目标、第二次转移、最终重启和私密牌面隔离。

## 失败复核

- 初始失败场景中原生阿奴只有普通出牌和结束行动，没有 JN10501 动作，证明行为未预先实现；加入服务端投影、合法性校验和转移事件后原断言转绿。
- 首次超时断言误把普通行动超时理解为状态完全不变；真实回合会继续经过补牌阶段。场景改为验证“原三张支付候选仍在阿奴手中且队友未收到牌”，保留并强化了不预先支付要求，没有修改引擎行为。
