## 规则证据

- SQLite：`OCCURS=R#GR`、`ONCE=0`，描述为自己的技牌阶段可把装备区装备转移给其他玩家，每转移一件立即补两张，一回合不能对同一角色反复使用。
- `PSDGamepkg/JNS/XJ405.cs:1574-1605`：合法性要求本人至少一件装备，并存在其他 `IsTared` 且不在 `RAM.Present` 的角色；输入恰好选择一件装备和一个目标，先发送标准装备转移，再 `G0DH` 摸两张，最后把目标加入 `Present`。
- `PSDGamepkg/XIR.cs:160-174`：进入 `GR` 技牌阶段前调用 `ResetAllPlayerRAM()`，说明 `Present` 的寿命是本技牌阶段。
- `PSDGamepkg/XIG.cs:1741-1900`：标准 `G0ZB` 先从来源移除装备，目标同槽已有装备时通过 `G0QZ` 弃置替换牌，再完成新装备导入。

## 已验证边界

- 只有存活的原生慕容紫英在自己的行动阶段、本人持有武器或防具且仍有未访问的其他存活目标时获得动作；服务端拒绝手牌、外来牌、未知牌、多张牌、本人/死亡/已访问目标和伪造技能。
- 每次只转移一件当前装备；武器进入目标武器槽、防具进入目标防具槽，目标原有同槽实体先进入弃牌堆，所有牌区保持守恒。
- 转移完成后复用统一确定性摸牌规划补两张；牌堆不足时从包含本次替换牌的新弃牌堆洗回，单例场景证明该替换牌可成为第二张。
- `turn.usedSkillTargetIds` 序列化保存本阶段已访问目标。相同目标不能重复，不同目标可继续发动；SQLite 重启保留集合，新回合创建时集合消失。
- 该技能不产生卡牌效果、选择实体或响应窗口；15 秒行动超时不发动、不移动装备且不摸牌。
- 装备槽和手牌数量公开，所摸两张牌的实例 ID 仅向本人投影。六连接场景逐席确认其他五份视图不含新摸牌 ID。
- JSON 检查点覆盖两次连续转移、重复目标拒绝、目标历史与完整事件回放；六个真实 WebSocket 覆盖首次转移、SQLite 重启、重复拒绝、第二次转移、最终重启和私密手牌。
- 旧 `ListOutAllEquips` 还包含额外装备和假装备；当前标准包+凤鸣玉誓运行时只有物理武器、防具槽且没有范围内假装备生产者，本收据不外推到特殊牌区。
