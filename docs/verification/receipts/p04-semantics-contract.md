# P04 确定性规则语义合同收据

日期：2026-08-19

## 结论

- `contracts/semantics.contract.json` 冻结规则集、协议、持久化和 RNG 的版本边界，并逐项关联 `P04-01` 至 `P04-15`。
- 对局生命周期、稳定身份、命令幂等、可序列化续算和单一顶层等待窗口均已有机器可读合同。
- 响应窗口使用父子效果和保存续算点表达；冰心诀取消准确的 `effectId`，取消被反制后原效果保持 pending，并从保存位置恢复。
- 伤害按照替换、加成、减免、批次应用、应用后触发、整批濒死检测的固定顺序结算；多人濒死按检测快照座位逐个救援。
- 服务端随机固定为版本化 `sha256-counter-v1`：秘密种子、计数器、拒绝采样和 cursor 范围记录，客户端输入不进入随机源。
- 操作窗口 15 秒，断联 60 秒后进入自动模式；断联不暂停当前操作期限，重启恢复绝对截止时间并幂等地产生至多一个超时命令。
- 命令中的 `clientIssuedAt` 仅供审计，不参与授权、排序或截止判断。
- 公开、队内、玩家私密和服务端秘密四个分区已固定；队友默认不能查看彼此手牌。
- 14 个场景覆盖正常、放弃、嵌套反制、伤害、多濒死、超时、断联、重启、无目标、重复/越权、隐私和同时团灭。
- C# 无法唯一确定的 6 个问题均已有 `SEM-001` 至 `SEM-006` 临时裁决，没有遗留给实现代码自行猜测的 open 项。

## 验证命令

```powershell
npm run semantics:verify
npm run typecheck
npm run test:unit
npm run check:fast
npm audit --audit-level=moderate
```

`semantics:verify` 同时执行关键反例模型：全员放弃关闭响应窗、双层取消恢复父效果、强制超时确定性选择、重启超时幂等、伤害修饰稳定排序和多人濒死座位顺序。

## 后续约束

P05 交互原型和 P06 技术探针必须消费本合同中的窗口、续算、超时、私密视图和场景 ID。若旧 C# 新证据推翻临时裁决，先更新合同、场景与本收据，再修改实现。
