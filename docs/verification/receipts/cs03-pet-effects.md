## 实现后的反向复核

1. 腐坏快照测试发现旧 NPC 校验只看目标数量，未核对已选交出者/接收者的合法关系；已同时补强 NJ06/NJ07。
2. 复核 `FiveElement.cs` 与 `XIG.cs` 发现按代码排序会改变死亡弃牌顺序。先保存失败测试，再改为水/火/雷/风/土，且每位死者先宠物、后同伴；精确顺序断言保留。
3. 全回归发现 Node Fetch `bad port`。原始失败未记录所分配端口；另以 10080 直接证明当前运行时的端口封锁。五个真实房间测试入口用实际 Fetch 健康探针，只对明确的 bad-port 错误关闭并重建服务器，最多八次；其它错误直接抛出。四条独立网络测试固定上述边界，不绕过安全列表。
4. 新探针暴露 JN20602 旧测试等待时刻硬编码为 `1000`，其窗口早已过期，原测试依赖连接抢在恢复定时器前完成。改为真实时刻的 15 秒窗口，保留变身/救援断言；失败后的数据库删除前先关闭仍存活服务。
