- 唐雪见支付手牌触发追打、韩菱纱死亡后选牌/放弃及自伤均实际执行，不仅覆盖“全部放弃技能”。父子来源图在消耗原效果栈帧后仍可恢复，拒绝循环或外来来源。
- 新增 9 项单元与 22 项重放/隐私/损坏状态场景，其中属性测试含 60 组固定种子可收缩混合手动/超时序列。每条命令正常执行、JSON 恢复后执行与领域事件重放相同；每个等待点验证 56 手牌类实体、46 遭遇实体和 34 角色分区守恒。
- 已自动模式玩家在窗口起点默认放弃，不消费 RNG；重复超时拒绝。非当前席无可用动作；等量不同私密手牌不改变其他五人的视图、动作或响应时序。
- schema 11→12 用真实 NPC 选择窗口验证：只增空战斗字段，保留既有选择、牌堆、RNG 和期限。损坏的战斗/伤害/效果绑定、提前就绪、孤立续算点与延长的期限被拒绝。
- 两项新增真实 HTTP/六 WebSocket/临时 SQLite 场景：建房准备选角后，仅注入初始怪物等待状态；非过期与过期各一条。分别重启响应窗口、救援窗口和完成状态；实际救援后只结束登场。六份投影保密，越权拒绝，重发救援命令不重复消费。
- 从 SQLite 读取包含连接事件的完整日志，重放与实际快照完全一致。过期响应有且仅有一次超时；最终 `monster.debut` 续算事件与救援同属一个命令版本。

## 失败证据与独立复核

1. 最初新增单元在缺少实现时失败（`cs03-debut-red.txt`）；实现后的首次规则场景暴露旧濒死 reducer 只放行 NPC 遭遇。修复为仅实际怪物伤害阶段放行，不放开整个遭遇阶段。
2. 宠物 fixture 原先只从牌堆移除实体，新初始状态已将它放在弃牌区，因此被守恒检查正确拒绝。修复测试夹具转移来源，未移除守恒断言。
3. 重放测试最初有括号语法错误；修正后的有效红测证明恢复接受孤立战斗、伪造来源和加长期限。随后新增真实校验，不以重建窗口隐藏损坏。
4. 新交叉 fixture 最初把冰心诀/仙丹编号及技能所属角色按数字猜错。复核 `setup-content.ts`、既有专项与 C# 后改为确切卡实例、XJ405/JN50501、XJ402/JN50203；断言使用真实技能行为。JN30201 对原本也受伤的自己追加一点伤害，依据 `XJ405.cs:626-636` 保持，而非修改规则迎合原测试预期。
5. 第一轮网络测试运行了尚未重编译的 dist，复现旧濒死阶段限制并导致超时/清理报错。先 `typecheck` 重编译后，两条网络场景与完整八条网络回归通过。`monster-debut:verify` 固定在网络前重编译，防止源码测试与实际服务使用不同实现。
6. 独立检查发现已消费效果帧后的追打、自伤不能靠字符串前缀验证归属，增加真实付费/死亡后分支红测和序列化父子来源图；不只是让校验忽略未识别子流程。恢复期间不延时，纯引擎不访问墙钟/网络/数据库。
7. 复核公开投影只挑选公开战斗字段，不输出来源图或其他玩家手牌；原型 E2E 与当前怪物接口证据明确分开。
