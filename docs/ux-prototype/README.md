# P05 浏览器交互原型合同

本原型只证明六人桌游在桌面和手机上“看得懂、点得准、复杂结算不迷路”，不裁定规则，也不使用未授权旧素材。模拟玩家视图与 `availableActions` 代表将来服务端输出；浏览器只能渲染这些动作并回传稳定 ID。

## 用户旅程

`创建房间 → 六人入座 → 准备 → 选角 → 对局 → 断联/重连 → 结算`

大厅与选角在正式纵向切片中实现；P05 对局原型保留入口状态并重点验证高风险操作面。没有账号、聊天、观战和旁观入口。

## 信息优先级

1. 正在发生什么：事件、出牌或救援对象。
2. 谁需要行动：自己、具体公开座位或笼统“等待其他玩家”。
3. 我能做什么：只显示 `availableActions` 中的卡牌、目标、确认和放弃。
4. 超时会怎样：剩余时间和“自动放弃/随机合法项”同时出现。
5. 公共盘面：六个座位的队伍、角色、HP、装备、手牌数量和公开状态。
6. 历史与详情：可展开，不挤占主操作区。

## 响应式结构

桌面 `1366×768` 使用“六席环桌 + 中央结算舞台 + 右侧记录 + 底部手牌/操作托盘”。关键按钮与当前效果在首屏内，记录区独立滚动。

手机 `360×800` 不是桌面缩放：顶部改为可横滑座位摘要，中央只保留当前事件和效果链，手牌横滑，操作托盘固定在底部安全区；次要记录进入抽屉。

## 操作语义

- 点选牌或目标只改变本地草稿选择，不立即提交。
- 选满合法数量后仍须点“确认”，防止触控误触。
- 可选窗口始终显示“本次放弃”，并解释只放弃当前窗口。
- 强制窗口不显示放弃，倒计时旁说明超时会从合法项中随机选择。
- 已过期动作全部禁用，并要求刷新到服务端最新视图。
- 等待文案只说“等待其他玩家响应”，不透露谁持有响应牌或哪些人有私密动作。

## 客观验收

- 所有指针操作目标至少 `44×44px`，正文和操作说明不低于 14px，非关键元数据不低于 12px。
- 键盘可用 Tab/Shift+Tab 移动，Enter/Space 激活，Escape 清空未提交选择或关闭抽屉。
- 焦点有明显轮廓；队伍、濒死和选中状态不只依赖颜色。
- 桌面和手机均无页面级横向溢出；手牌/座位横滑区除外且有可见提示。
- 支持 `prefers-reduced-motion` 和手机安全区。
- 长说明、大量手牌/技能不会把确认按钮推离可达区域。
