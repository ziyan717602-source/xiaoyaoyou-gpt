# CS03-03A 揭牌、选择与结算归属

状态：路由及数值原语已实现；不是完整战斗或 NPC 效果迁移。正式回合仍保持原边界，等待 CS03-03B/C/D。

## 可执行语义

- `beginEncounterResolution` 消费 CS03-02 的 ready-reveal 决策。放弃仅揭弃一张并标记奖励 1；战斗揭牌按真实类型进入 `monster-effects` 或 `npc-options`，牌离堆但不入弃牌区。
- `openNpcDecision` 只接受服务端合法性计算器给出的该 NPC 行动子集，按数据库行动顺序固定。**缺少行动处理器不是“无合法行动”**，调用方必须显式拒绝未实现处理器，不能据此跳牌。
- NPC 行动窗口属于当前玩家，15 秒。剩余牌堆非空可放弃；最后一张 NPC 有合法行动则不能放弃，超时按规范 ID 顺序和记录的 RNG 选择。晚到超时仍以原 deadline 为结算时间，不延长后继窗口。
- 放弃或无合法行动：弃置当前 NPC 并继续揭牌，保留本轮支援/妨碍，不重问。无合法行动且无下一张时立即进入 `deck-exhausted`，没有奖励。
- 选择行动只生成带稳定 ID 的 `pendingEffect`。`finishNpcAction` 是引擎内部续算完成钩子，必须在具体处理器及其伤害、濒死等子效果全部完成后调用。普通 NPC 入弃牌区；NJ09 入当前玩家同伴区，不能同时存在两处。成功行动的基础奖励为 2。
- `finishMonsterBattle` 同样只是具体怪物效果之后的内部收尾钩子，不允许客户端提交“我赢了”。失利或不可收服时弃置，胜利收服时移入宠物区。同属性已有宠物时，必须由接收者在旧/新宠物中保留一只；15 秒超时按 `SEM-002` 的规范 ID 排序随机，另一只弃置。旧/新展示顺序不影响随机结果。
- 奖励字段只是待消费的基础数量，不直接摸牌；奖励相关技能与清理仍由正式回合处理。正常放弃、NPC 成功、怪物完成后空堆在回合结束时计分；不能执行的末张 NPC 立即计分。

## 战力与计分

`evaluateBattle` 使用当时的数值，不硬编码角色初始战力。当前玩家战力无须命中；有效支援、妨碍、额外参战者只有命中才加战力；自己支援不重复计算。命中规则为 DEXi 正数强制命中、负数强制不命中，否则身法至少等于怪物闪避。两侧分别加修正后取不小于零；平分时当前玩家一侧获胜。

存活角色 STRi 的必胜/必败优先于战力比较；按稳定原始入座顺序选择首个非零项，不依赖数组/对象传入顺序。旧 `XIS.cs` 和 `VW/Aywi.cs` 按玩家加入顺序构造 Garden，随机 UID 与该顺序分离；新引擎的稳定 seat 与 `SEM-007` 对应。死亡角色的强制结果不参与。

`evaluatePetScore` 只累计存活持有者宠物的当前正战力。不是怪物等级、卡面初始值或手牌数。红队必须严格较高才能获胜，平分（包括双方为零）蓝队胜。这与“双方全部死亡”的存活胜负规则是不同终止原因，正式接入时不得覆盖后者。

## 身份、隐私和恢复

- `encounter-definitions.ts` 包含范围内 20 怪物和 26 NPC 的事实元数据；不含旧图片、程序集或整段效果文本。卡牌元数据存在不代表具体效果完成。
- `assertEncounterOwnership` 检查主堆、弃堆、持有牌、宠物、同伴中的唯一身份和宠物属性槽；后备 NPC 堆由 MatchState 外层保持隔离。属性测试合并后备堆检查全部 46 个唯一 ID。
- NPC/宠物等待均序列化 owner、choiceId、候选、openedAt、deadlineAt；恢复不重抽随机、不重开期限。
- 玩家投影没有未来牌堆或 pendingEffect 内容；只有决策者获得候选与动作。六份投影及两个不同隐藏牌序世界有直接测试。
- 错误和身份检查在纯内核层；网络版本、重复命令收据、Actor 串行化和数据库事务仍由 M06/正式 CS03 适配层处理。本节点的 JSON 恢复不是 SQLite 重启证据。

## 证据与测试

权威证据是只读 C# 源码加 SQLite，而非黑盒等价认证。源码位置见 `contracts/encounter-resolution.contract.json`。关键来源：`XIR.cs:371-452,1016-1078`、`Board.cs:211-234`、`Pond.cs:19-27`、`Kitty.cs:10-205`、`NC303.cs:675-694`、`XI.cs:1200-1223`、`XIG.cs:716-730`。

运行 `npm run encounter-resolution:verify`。单元测试进入 `check:fast`；属性/序列化测试进入 `test:replay`，两者均在 `check:full`。

测试区分两类证据：直接验证揭牌、放弃、强制选择、归属和战力；显式调用完成钩子只验证收尾，不声称执行了 46 张牌的具体效果。60 组可收缩种子序列有界推进、逐步恢复和实体守恒，也不是完整六 Bot 对局。
