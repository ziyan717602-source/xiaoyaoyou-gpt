# CS03-03B-02-OPTIONS：NPC 行动选择、放弃与强制超时

契约：`contracts/npc-options.contract.json`。本节点把揭示中的 NPC 接入实际 `MatchState`、通用命令和既有九个行动处理器；不再要求入口预先替玩家选定行动。证据等级为 C# 源码及已对账的 SQLite 元数据，不声称新增黑盒等价轨迹。

## 规则与来源

`PSDGamepkg/XIR.cs:1016-1078` 遍历 NPC 声明的行动，经过各自 Valid 判断后仅给当前玩家发出选择。末张 NPC 取消时重发强制提示，无合法行动则返回 NO_OPTIONS。`XIR.cs:406-454` 把未执行行动的 NPC 弃置并继续揭牌；无剩余主牌时进入即时计分；执行行动后进入奖励阶段。

新入口 `beginNpcOptions` 使用既有 NJ01/NJ06/NJ07/NJ08 Valid 条件，不让客户端提供合法性，也不把缺失处理器伪装成没有合法行动：

- 主牌堆有后续牌：允许空选择放弃；15 秒超时放弃，不消费 RNG。
- 末张 NPC 且有合法行动：不允许空选择；超时把合法行动按 canonical ID 排序，用已记录种子随机选一项并进入真实处理器。
- 没有合法行动：弃置 NPC 并继续揭牌，连续无选项 NPC 使用有界循环推进；停在下一选择、持有的怪物或即时计分续算状态。怪物和计分仅交接续算，不在本节点假装执行。
- 选定行动：在同一命令事务内追加选择事件和实际效果事件；一个命令版本、连续事件序号。NJ01 换角、NJ07 宠物交换、NJ06 私密给牌和伤害/濒死仍由既有处理器执行。

## 等待、投影与恢复

`npcDecision` 与通用 `pendingChoice` 双向绑定：实际持有 NPC、行动者、揭牌次数、合法项、是否可放弃、开启/截止时刻、续算标识必须一致。损坏快照报错，不补建或延长窗口。现有 schema 11 已有这些字段，本节点不新增持久化字段。

行动者只使用根级 `availableActions` 的 `submit-choice`；其他五人只收到公开等待摘要。实际玩家视图移除纯路由层的第二套嵌套 `choose-npc-action`，避免客户端面对两套动作权威。其他玩家的同样数量、不同身份手牌不能改变所见动作或等待数据。

新窗口保持 15 秒；断联不延长截止，自动模式沿用窗口开启时刻决策。事件重放重新计算行动、弃置、续算与 RNG 游标报告，不信任日志中的任意结果。网络集成从真实 HTTP 六人开局开始，只注入“已揭示、未选行动”的初始场景；之后所有命令、超时、断线、重连与 SQLite 重启均由真实服务处理。

## 验证与边界

`npm run npc-options:verify` 覆盖选择/连续揭牌/九行动、实体守恒、JSON 恢复、可收缩种子序列、六人隐私以及真实六连接。网络测试读取落盘事件，重放到与最新服务器快照完全相等；手动选择只增加一个版本，超时仅结算一次，再次重启不重做。

NPC 行动选择与既有处理器现已连通，但 CS03-03B 不单独代表完整遭遇回合。怪物登场、胜败、战牌与宠物/同伴消耗由 CS03-03C 继续；CS03-03D 才接管正式 M03 回合并实际执行奖励/即时计分交接。受保护牌等既有内容依赖仍保留。55 项 CS03 目录状态不因本节点整体提升，既有浏览器 E2E 只是回归，不是新增 NPC UI 或完整牌局的证明。
