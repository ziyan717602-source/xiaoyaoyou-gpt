## 当前 WQ04 实现

魔剑只有一张物理实例 `xyy.card.wq04@50`。玩家视图在它位于自己的手牌或武器槽时提供同一个显式 `mode: pawn` 动作；其他玩家即使能看到公开装备，也不获得该动作。服务端事件记录 `sourceZone`，从权威手牌或武器槽移除实例，放入弃牌堆，再通过统一牌堆/RNG 管线补两张。该模式没有目标、没有效果栈、没有响应窗口；伪造其他装备、其他玩家的魔剑或错误目标均拒绝。

## 当前 WQ02 实现

TP02 普通治疗、TP02 濒死救援与 JP03 队伍治疗现在先生成统一的确定性治疗项，再由事件归约器复算并应用。治疗项记录基础值、修正后值、元素、规范化旧版 `HPEvoMask` 标志、HP 前后值和实际生效的装备实例；同一目标的多项治疗按顺序滚动 HP，因而 JSON 事件重放和 SQLite 重启不会依赖进程内回调。

目标自己的武器槽为 `xyy.card.wq02@48` 时，每个正数且不含 `TERMIN_AT` 的治疗项恰好 +1；判断与出牌者无关，所以其他玩家用 TP02 救援持杖者仍加成。0 点、`TERMIN_AT`、未装备以及治疗其他玩家均不加成。JP03 同时保留 `FROM_JP` 来源标志。当前还没有装备失效状态；该状态落地后，统一入口必须在这里增加 enabled 判断。

## 当前 FJ03/FJ04 实现

旧 C# 的 `HPEvoMask` 是可组合位掩码，不能继续用“普通/倾慕”二选一字符串模拟。当前事件模型把十二个旧标志保存为固定顺序、不可重复的 JSON 数组；例如天雷破是 `["from-jp"]`，不可直接免疫的技牌伤害是 `["immune-inavo", "from-jp"]`。隐蛊改为判断“不含 `tux-inavo`”，因此来源标志和可免疫标志能够共存。

伤害计划在打开隐蛊窗口、扣 HP 和进入濒死以前读取目标的权威防具槽：

- `xyy.card.fj03@54` 对每个正数项减 1，但跳过 `termin-at/decr-inavo`；减到 0 的项从批次删除。
- `xyy.card.fj04@55` 删除正数 `from-jp` 项，但 `immune-inavo` 绕过免疫。非技牌来源不受影响。

被动结果属于确定性伤害计划，事件归约、JSON 重放和 SQLite 重启都会复算，不依赖进程内回调。FJ04 的战力 +1 等待 CS03；装备失效来源等待 CS02，届时统一装备读取必须加入 enabled 判断，因此两张卡暂保持 partial。

## 当前 FJ01 实现

存活但 HP=0 的当前濒死角色在自己的救援优先权到来时，如果防具槽仍是 `xyy.card.fj01@52`，会看到显式 `activate-rescue-equipment` 动作。选择后服务端验证角色、当前濒死目标、优先权和权威防具槽，弃置五彩霞衣，再通过统一治疗计划回复基础 2 点；因此同时装备天蛇杖时实际回复 3 点。随后重新扫描同一濒死批次，继续处理其他零 HP 角色。

该动作可放弃，15 秒超时仍等价于当前救援优先权 pass；其他玩家不能替持有者发动，已离开防具槽或伪造目标会被拒绝。FJ01 的战力 +1 与装备失效状态仍等待 CS03/CS02，所以目录项保持 partial。

## 当前 FJ05 实现

伤害批次会把拥有 `xyy.card.fj05@56` 且至少有一个可免疫自身伤害项的玩家加入 owner-only 响应顺序，即使该项含 `tux-inavo`、不能使用隐蛊。玩家可选择显式 `activate-damage-equipment`：服务端验证当前优先权、伤害效果和防具槽，弃置踏云靴，删除自己的全部正数且不含 `decr-inavo/immune-inavo` 的项，再通过统一治疗计划回复基础 1；同时装备天蛇杖时回复 2。

发动等价于该玩家完成本伤害窗响应，剩余玩家和剩余伤害项继续原序结算；放弃或 15 秒超时不支付装备。`decr-inavo/immune-inavo` 项既不被删除，也不会单独让玩家获得虚假动作。FJ05 的命中 +1 与装备失效状态等待 CS03/CS02，因此保持 partial。
