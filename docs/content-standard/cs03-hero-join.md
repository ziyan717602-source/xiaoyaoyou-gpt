# CS03-03B-02-JOIN：NPC 换角、复活与被动重载

契约：`contracts/hero-join.contract.json`。C# 源码和只读 SQLite 为证据，未宣称黑盒等价。

## 真实行为

NJ01 分两次由当前玩家选择：先选己方有手牌的活人支付，再选己方任意位置加入。接受第二次选择才扣除全部手牌；可以同一人支付并换角，也可以复活死者。生命设为手牌数的两倍、上限为新角色最大生命，不是治疗，不走天蛇杖等治疗修正。这里仅接遭遇来源，C# 对 JP/SJ 来源的最多 3 点不是遭遇规则。

`NC303.cs:67-119`、`ContentRule.cs:13-68`、`Hero.cs:145-156,214-220` 明确了可加入性。同角色、同位体只有存活时阻挡；原型关系即使死亡也阻挡。SQLite 的 XJ103/XJ304 有 `@` 原型，XJ207/XJ507 没有；不能把全部变身角色当成同一种规则。四个变身角色均不能直接 NJ01 加入。

`XIG.cs` 的 G0OY/G0IY 先卸载旧角色效果，再载入新角色并恢复原装备、宠物。新实现复用已验证的武器技能和宠物属性入口，清空行动者的旧角色使用次数，保留其他玩家的回合记录以及实际牌区。GL04 的对方武器失效不因换角清除，也不关闭实体武器关联的 JN10401/JN10601。

同一入口用于 JN20602：此前变身重置基础数值时丢掉已有宠物属性。增加真实濒死→放弃救援→变身的失败场景后修复，而不是只测辅助函数。

## 身份、恢复与隐私

- schema 11 在遭遇运行状态中保存角色弃置和禁用集合；34 个 canonical 角色按活动、弃置、禁用、可用分区检查守恒。死者的 `heroId` 是历史引用，C# 允许这个角色在另一位置加入，不代表第二张实体。
- 换出身份进入弃置，换入身份从弃置移除。死者历史引用若对应另一活人，不能再把它加入实体弃置区。
- v10 升级只添加此前不存在的两个集合，不重置选择、时间、连接、随机或属性；不臆造旧版本未记录的换角弃置历史，也不猜测旧快照属性中是否包含临时修正。历史宠物属性错误不声称可自动修复。
- 两个等待点均为强制选择、15 秒；超时按合法 ID 排序后种子随机，自动模式立即决定。恢复时检查支付者、阵营、加入性、步骤、选项、截止和选择所有者，事件报告必须可重新计算。
- 支付前手牌只给所有者；支付后的弃牌属于公开区。其他五个视图只展示等待摘要，不能看到私密手牌。

## 边界

所有 NPC 的 Valid 条件已经实现，开始执行前必须通过。[CS03-03B-02-OPTIONS](cs03-npc-options.md) 已将它们接入真实 `MatchState` 的行动选择/放弃/末牌强制/无选项继续翻牌窗口，并有独立命令、超时与恢复测试；不是只依据纯路由测试。

受保护手牌、未迁移角色 token/ROM/借技、宠物封印/失效/爆发及其生产者仍需后继内容处理；不能据此标记相关技能完整。怪物效果、正式回合接管和浏览器整局仍未完成，55 个 CS03 目录条目状态不提升。
