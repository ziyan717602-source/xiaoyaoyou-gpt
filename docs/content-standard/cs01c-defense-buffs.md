# CS01C 防御与战力牌合同

状态：TP03 普通伤害防御边界已验证但保持 partial；TP04 与 ZP01–ZP04 的规则和依赖已冻结，等待真实怪物牌堆与战斗生命周期。

## 冻结规则

- 隐蛊：当前伤害批次中只要自己存在大于 0 的非 `TUX_INAVO` HP 伤害，即可支付此牌；结算成功后删除该批次中属于自己的全部非 `TUX_INAVO` 伤害项。数据库文本中的“倾慕除外”对应旧实现的 `HPEvoMask.TUX_INAVO`。隐蛊是技牌效果，因此自己也先进入冰心诀响应链；若被抵消，原伤害继续。
- 洞冥宝镜：任意玩家决定是否翻取怪物牌前，对一名可指定的同队玩家（包括自己）使用；该玩家私下查看怪物牌堆顶一张，再原样放回。没有怪物牌堆和遭遇前窗口时不实现替代行为。
- 金蝉脱壳：仅参战者可用，强制本场战斗直接到终止阶段，不进行胜负结算；旧数据库注明不能被净衣咒响应。
- 天罡战气：参战且命中后，把当前大于 0 的基础战力（含装备、宠物）再加一次，生命周期仅为本场战斗。
- 金蚕王：参战且命中后，本场个人战力加 3。
- 天玄五音：未参战也可用，选择一方，本场该方战力加 2。

## 只读旧版证据

- 数据库 `Tux` 的 TP03/TP04/ZP01–ZP04 行提供 `OCCURS`、目标、说明及金蝉脱壳的特殊限制；公开仓库不包含数据库本体。
- `JP06.cs:523-558`：隐蛊要求当前伤害批次有自己的正数、非 `TUX_INAVO` 项；成功后过滤自己的全部非 `TUX_INAVO` 项。
- `JP06.cs:560-569` 与 `JNSBase.cs:157-160`：洞冥宝镜选择可指定同队玩家（集合包括自己），查看怪物牌堆顶后放回。
- `JP06.cs:708-744`：四张战牌分别跳转战斗终止、复制正数基础战力、个人战力加 3、指定一方战力加 2。

## 当前实现边界

伤害修正完成后，引擎创建可序列化的 `damage-batch` 效果与绝对 15 秒响应窗口，HP 和濒死状态尚不改变。每个具有正数可防伤害的目标都取得一次优先权，不以是否持有隐蛊决定是否开窗，避免从时序或动作推断手牌；只有当前目标的玩家视图包含其隐蛊实例和放弃操作。

打出隐蛊立即把实体牌移入弃牌堆，并创建普通技牌子效果。其他存活玩家可用冰心诀响应；成功则从父伤害批次删除该玩家的全部普通伤害项，失败则恢复父窗口并继续伤害。窗口、父子效果、剩余伤害项、期限和已响应玩家全部保存在状态与事件中，可在 JSON/SQLite 重启后继续。超时按可放弃操作处理，不自动消耗隐蛊。

`TUX_INAVO` 是伤害计划的显式掩码，不依赖 UI 文本判断；此类伤害直接进入 HP/濒死结算。TP03 的复制、转移和流转模式依赖 FJ02 与后续技能，故目录项保持 partial。TP04 与四张战牌不使用假牌堆或假战斗状态，等 CS03/CS01D 前置闭合后继续。

机器可读版本见 `contracts/defense-buffs.contract.json`。
