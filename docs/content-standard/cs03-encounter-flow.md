# CS03-02 遭遇决策状态机基线

状态：纯规则内核已验证，尚未接管正式回合流程。

## 旧版行为

- `PSDGamepkg/XIR.cs:190-299` 先收集存活同队玩家，当前玩家决定放弃或选择支援项；选择自己仍表示进入战斗，但不会额外重复计算自己的战力。放弃会公开揭示主遭遇堆顶并将其弃置，然后进入奖励阶段。
- `PSDGamepkg/XIR.cs:300-363` 仅在决定战斗后询问妨碍；决定者是 `Board.Opponent`，可不选妨碍项。
- `PSDBase/Board.cs:131-174` 按当前玩家在本队的序号寻找敌方同序号玩家；若该玩家死亡，向后寻找下一名存活敌方，最后回绕到首名存活敌方。
- `PSDGamepkg/Artiad/Coaching.cs:8-119` 表明支援/妨碍位置并非只容纳玩家。旧流程还允许规则钩子追加宠物或特殊牌，因此新模型使用带 `kind` 的参与者引用，不能只存一个玩家 ID。

旧联机端允许同队成员提交“建议”，但最终权威决定仍只属于当前玩家或对应敌方。当前范围明确不实现聊天；建议不是规则命令，也不进入服务端状态、事件或超时体系。

## 确定性状态机

`packages/engine/src/encounter.ts` 固定以下可 JSON 序列化阶段：

1. `awaiting-support`：当前玩家独占 15 秒决定窗，基础候选为按 `turnIndex` 排序的全部存活同队玩家（含自己）。
2. `awaiting-hinder`：选择战斗后，对应存活敌方独占新的 15 秒决定窗；基础候选为全部存活敌方。
3. `ready-reveal`：两侧决定已经固定，下一步只能揭示主遭遇牌。
4. `completed`：放弃时揭示的牌已经进入公开弃牌区。
5. `revealed`：战斗时揭示的牌离开牌堆并由状态机持有，等待怪物或 NPC 结算。
6. `deck-empty`：空牌堆显式终止本链，不以 `undefined` 或进程异常表示。

支援窗超时固定为放弃，妨碍窗超时固定为无人妨碍。只有 `decisionOwnerPlayerId` 对应的玩家投影会获得动作；参与战斗的宠物或特殊牌永远不会取得输入权限。

## 接入边界

本节点刻意不修改 `end-action` 的现有 M03 跳过流程。若现在开放“选择战斗”，揭出怪物后尚无完整命中、战力、战牌、濒死续算和 NPC 行动闭环，真实房间会进入不可终止状态。正式接入必须同时满足：怪物与 NPC 两类牌都有可结束的路由；放弃、战斗、超时、掉线自动模式和 SQLite 重启均可继续；客户端动作全部来自服务端投影。在此之前 55 个 CS03 内容项仍保持 unstarted。
