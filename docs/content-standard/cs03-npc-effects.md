# CS03-03B-01：NPC 具体效果与可恢复续算

本节点使 NPC 真正改变 `MatchState`，不再只调用路由完成钩子。对应 `contracts/npc-effects.contract.json`；仍不是完整 NPC/怪物战斗或正式回合接入完成。

## 行为与来源

`PSDGamepkg/JNS/NC303.cs` 的 NJ02–NJ09 与只读目录行动绑定是主要证据。NJ02 由当前玩家选择任一活人治疗 1，沿用无玩家来源、无属性及 `FROM_NMB`；NJ04 当前玩家摸 1；NJ03 先自伤 1、完成伤害结算后使已选目标摸 1；NJ05 对已选活人伤害 1。伤害使用既有 TP03/FJ05 减伤响应、濒死、救援、死亡、遗物与胜负管线，NPC 的持有牌和续算指针在等待中保留。

NJ06 由当前玩家选交牌者及其另一名活队友，再由交牌者本人私密选择一张手牌。选择目标不会公开该玩家手牌。NJ08 选有手牌的活人后按种子随机弃一张；C# 的匿名背面确认输入不参与最终随机弃牌，当前实现不重建这个无效确认步骤。受保护手牌联动仍有显式后继依赖，未声称完成。

NJ09 只实现将正在结算的 NPC 收为同伴。战斗中消耗同伴增加战力属于 CS03-03C。`XIG.cs:389-410` 明确死亡会清理同伴；新同伴区接入既有死亡清理和遗物分支，不使死者永久拥有 NPC，也不提前丢弃当前仍在结算的 NPC。

## 确定性与恢复

- `encounterState` 保存揭牌路由、宠物/同伴归属和 NPC 执行步骤。schema 8→9 只添加空运行状态，保留原牌堆、私密查看历史和 RNG。
- 使用现有 `submit-choice`、`availableActions`、领域事件和系统超时管线，不增加绕过 Actor 的客户端入口。
- 多步给牌的每次选择均有独立 15 秒截止。不能放弃的选项按 canonical ID 排序后使用种子随机；断线不延期，已有自动模式使用窗口开启时刻。
- `npc.operation` 记录确定性结果，事件重放重算并校验，不能直接信任客户端选择者或伪造结果。
- 恢复校验关联实际 NPC、行动、执行步骤、目标数量、选择所有者、选项和截止；损坏快照报错，不生成缺失选择。
- NPC 私密选项仅出现在其所有者视图；公开摘要只含行动、步骤、等待玩家和期限。伤害阶段的具体等待对象仍由既有响应/濒死视图提供。

## 明确裁定

[SEM-010](../rules-semantics/nj03-post-death-draw.md) 记录 NJ03 自伤死亡后仍可能摸牌的 C# 组合路径。暂行语义为：先完成伤害/死亡；来源死而已选目标活则仍摸，目标死或对局结束则不摸、不消耗牌堆。此项是公开记录的临时偏离，不声称经过黑盒等价验证。

## 尚未闭合

NJ01 角色加入、NJ07 宠物交换、完整 NPC 行动合法性、怪物登场/胜败/宠物效果、受保护牌及正式遭遇回合入口仍未完成。七个具体处理器不等于 55 项 CS03 内容完成；奖励字段尚需后继真实回合发牌。测试从已选 NPC 的真实状态 fixture 起步，不能据此宣称玩家能从行动阶段自然进入遭遇并完成整局。

专属验证：`npm run npc-effects:verify`。属性测试在每个选择/超时后重建状态并重放事件，检查六视图以及 56 张手牌类牌、46 张遭遇实体守恒。六连接集成在给牌私密等待点真实关闭/重开服务器与 SQLite，再提交选择并重复命令，验证只转移一次。
