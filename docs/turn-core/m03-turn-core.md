# M03 确定性回合核心

M03 把 M02 的开局状态接入正式命令、事件、卡区和轮转管线。它提供后续响应栈、伤害和濒死流程共用的稳定动作边界；规则仍只在服务端执行，浏览器只能根据自己的 `availableActions` 提交动作。

## 阶段与轮转

可序列化阶段固定为 `turn-start → event → action → encounter → battle → reward → discard? → turn-end`。M03 尚无事件牌、遭遇或战斗内容，因此这些阶段仍各自产生确定性阶段事件后自动通过，不能靠 UI 猜测跳转。后续回合从 `turn-start` 经空 `event` 进入 `action`；M02 开局直接落在首位玩家的 `action`，避免为已经完成的初始化伪造历史事件。

无战斗分支在 `reward` 摸一张，符合 C# `XIR.cs` 的 `Board.Battler == null ? 1 : 2`；战斗后的两张奖励留给真正实现战斗结果的节点，M03 不伪造 `Battler`。玩家手牌超过默认上限三张时进入强制 `discard`，必须一次提交恰好超出的、属于自己手牌且互不重复的实体 ID。完成后按 seed 回合顺序寻找下一名存活玩家。

## 卡区、出牌与目标

56 张物理卡实例在任何状态都必须恰好属于手牌、武器、防具、摸牌堆或弃牌堆之一。摸牌堆顶是数组首项；不足时用保存的 `sha256-counter-v1` RNG 对弃牌执行 Fisher–Yates 后继续摸，事件记录实际实体和结束 cursor，重放不读取系统随机。

M03 只打开三类由 C# 证据可独立闭合验证的基础动作：

- `JP04 鼠儿果`：使用者从所有存活玩家中选择一人，目标摸两张；使用牌进入弃牌。
- `WQ01..WQ05`：只能给自己装备到武器位；旧武器进入弃牌。
- `FJ01..FJ05`：只能给自己装备到防具位；旧防具进入弃牌。

其余卡牌并非被当成无效果，而是在对应内容、响应、伤害节点完成前不出现在 `availableActions`。伪造未知卡、打出不在自己手里的卡、错误目标、非当前玩家行动和错误弃牌都稳定拒绝且不改变状态。

## 胜负与隐私

轮末若只剩一个存活队伍，该队获胜；双方均无存活角色则平局；两队都有存活角色则继续。死亡与胜负重算的触发时机属于 M05，但 M03 已提供同一个确定性终局函数。

公开投影包含当前玩家、回合号、阶段、各玩家手牌数量、装备和胜者。只有本人收到自己的手牌、可出卡动作和弃牌候选；其他五人以及队友都只收到数量。摸牌堆顺序和 RNG seed 永不进入玩家视图。

## 恢复与验证

一个命令可以产生多个严格递增事件，但共享同一个新 match 版本。Actor 将事件、幂等收据、版本和等待点快照原子提交。纯测试逐事件重放并做 JSON 往返；真实六连接测试在完成一次奖励摸牌、弃牌和轮转后重启服务，再验证同一玩家视图和旧命令幂等结果。

M03 将 match schema 从 v2 提升到 v3。恢复路径显式把 v2 快照迁移为 v3：补入回合/胜者字段以及默认手牌上限和空装备槽；未知版本拒绝加载并保留原始数据，不能靠 TypeScript 断言把旧 JSON 静默当成新状态。

```powershell
npm run turn:verify
npm run check:full
```
